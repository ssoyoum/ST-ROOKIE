# Ollama 제선 검증 결과 — 2026-10-13

## 실행 환경과 서비스 주소

- 실제 로컬 `qwen2.5:3b` Q4_K_M, Ollama `http://localhost:11434`, CPU 실행.
- Ollama 웹 앱: `http://localhost:3001`. `/api/status`에서 `provider: Ollama`, `model: qwen2.5:3b`, `connected: true`를 확인했다.
- 체크포인트 전용 화면: `http://localhost:3001/checkpoint-test.html?user=ollama-demo`. 웹에서 제출하면 서비스 DB에 기록한다.
- 자동 체크포인트 검증은 독립 `:memory:` DB와 임시 포트를 사용했다. 서비스 학습 기록을 변경하지 않았다.
- 최종 루브릭은 제선 세 개념이고 현재 `reviewed: false`다. 다른 공정의 체크포인트 검증은 포함하지 않는다.

## 전체 체크포인트 API 흐름

실행 명령: `npm.cmd run test:ollama-checkpoint`

| 검증 항목 | 실제 결과 |
|---|---|
| 시작 → 준비 → 첫 질문 | `awaiting_ready` → `awaiting_answer` |
| 명백한 오답 제출 | `wrong` 판정이 DB에 저장됨 |
| 부가 설명·다른 재확인 질문 | 설명과 질문을 반환하고 `awaiting_recheck`로 진행 |
| 재확인 정답 | `correct`로 저장 후 다음 개념 진행 |
| 나머지 두 개념 정답 | 각각 `correct` |
| 최종 완료 | `completed`, 세 개념 각각 1점, 이해도 100%, 해금 |
| 결과·대화 복원 | GET으로 같은 결과와 재확인 대화 기록 복원 |
| 진도 저장 | 이해도 100%, 해금, 진행 중 시도 없음 |

실제 모델 호출 9회, 전체 369.5초(약 6분 10초), 개별 호출 9.6~158.9초. 합성 정답은 해당 개념의 루브릭 핵심 요소를 연결해 만들었다. 이것은 실제 모델을 통한 HTTP·상태·저장 검증이다. 사람 답변의 채점 정확도나 브라우저 화면을 직접 조작한 검증을 뜻하지 않는다.

원본: `llm/eval/results/ollama-checkpoint-1791875041152.jsonl` 및 같은 이름의 `.summary.json`(Git 제외).

## 채점 평가 스크립트

실행 명령: `npm.cmd run eval:ollama -- --set smoke --limit 7`

전체 smoke 29개 중 initial/recheck와 판정 종류를 나누어 선택한 7개 표본을 실행했다. 기존 평가 세트, 최종 루브릭, 평가자 프롬프트와 서버의 출력 검증을 사용했다. Gemini fallback이나 판정 강제 보정은 없다.

| 항목 | 결과 |
|---|---|
| 기대 판정 일치 | 4/7 (57.1%) |
| 부분 정답을 오답으로 판정 | 2건 |
| 판정 필드 일관성 오류 | 1건 |
| 연결 오류 | 0건 |
| 케이스 소요 시간 p50 / p95 | 27.8초 / 34.4초 |
| 종료 코드 | 1 — 발견한 불일치·형식 오류를 실패로 보고 |

발견한 문제:

1. 소결 설명 “철광석을 구워서 덩어리로 만드는 공정이요.”는 기대값 `partial`이지만 `wrong`으로 판정했다. 알고 있는 부분을 인정하는 루브릭 적용이 부족하다.
2. “소결이 정확히 무슨 뜻이에요?”는 `assisted`가 기대값이다. 모델은 `assisted`를 반환했지만 `explain_from`을 빠뜨린 상태(`null`)가 2회 이어져 서버의 일관성 검증을 통과하지 못했다.
3. 재확인 답변 “전로에서 용강을 만들 수 없어요.”는 기대값 `partial`이지만 `wrong`으로 판정했다.

원본: `llm/eval/results/ollama-evaluator-smoke.jsonl` 및 `.summary.json`(Git 제외). `--resume`으로 7개 기록을 재사용했고 추가 생성 호출 없이 같은 불일치와 종료 코드 1을 반환했다. 기록에 모델·서버·프롬프트·루브릭·응답 스키마의 지문을 남겨 설정이 바뀌면 다시 실행한다.

빌드·타입 검사와 기존 코드 테스트 229개는 통과했다. 실제 모델 채점 평가의 불일치·형식 오류는 이 코드 테스트 통과와 별도로 보고한다.

## 결과에 따른 다음 작업

- 체크포인트 전체 진행과 저장 경로는 실제 Ollama로 동작한다.
- 현재 3B 모델은 이 기초 표본에서도 부분 정답·힌트 요청을 안정적으로 처리하지 못했다. 채점 판정은 자동으로 정답으로 바꾸지 않았으며, 프롬프트 개선과 다른 모델의 같은 세트 비교가 필요하다.
- CPU 시연 속도도 개선 대상이다. 생성 시간과 입력량을 줄이는 작업, 질문 다듬기 호출의 필요성 검토, GPU 환경에서의 비교가 다음 단계다.
- smoke 전체 29개, hard 세트, 실제 사람 답변의 정확도 평가, 다른 공정, GPU·GKE 운영은 이번 결과에 포함하지 않는다.

재실행 방법은 [Ollama 로컬 안내](ollama-local.md)를 따른다. 새로운 실제 평가 기록을 만들려면 `--records llm/eval/results/ollama-smoke-new.jsonl`을 지정한다. 기존 결과 재사용은 `--resume`을 사용한다.
